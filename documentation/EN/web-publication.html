After validating the report, publish the report and data in the expected locations, then create the country page in WordPress. The webpage reads data from the published CSV, so its quality depends on the files put online.

What you publish

The country page brings together a full report and a web visualisation of results. The HTML report remains the detailed source; country-page charts are fed by exported tables published as CSV.

Use the same three-letter ISO code in GitHub, the dataset name and page settings. For Madagascar, for example: MDG.

Before you begin

Validate the report, exported data and key messages. Any change to scores or labels must be made before publishing the CSV and completing the final WordPress page check.

Publication workflow

Follow these steps in order so the WordPress page can read the report and data available online.

Upload the report

Add the final report to GitHub, in the country folder.

1. Publish the report in GitHub

The final report must be available in the CTI repository before adding its link to the country page.

ActionLocation / ruleCheck
Create or open the country folder/summary/ISO-code/, for example /summary/MDG/.The ISO code is identical to the one used for data and the page.
Add the validated reportAdd the final HTML version of the report to this folder, following the repository naming convention.Open the file from GitHub and check its display and internal links.
Keep the reference versionAlso add the PDF or Word version if it is officially distributed.The country page “full report” link points to the correct version.

Good practice

Use a pull request when the repository is shared. It enables review of the link, folder name and report before public release.

Do not change the ISO code

Folders, data and page must all use the same code. A mismatch between MDG, Madagascar and another identifier generally prevents links or automatic loading from working.

2. Copy exported data into Google Sheets

The report export file provides the data used in charts. Copy its data into the Google Spreadsheet that feeds the site.

A

Open the publication sheet

Use the central CTI Google Spreadsheet and open or create the sheet for the country and module.

B

Paste values

Paste exports as values, keeping the header row and standardised columns.

C

Check the structure

Check in particular Country, Module, Year, Group, Name, Label, Series and Value.

D

Check labels

Keep the codes and labels required for charts, including translation columns where used.

Checks

  • There is only one header row and no blank row at the start of the sheet.
  • Numeric values remain numbers and use the same decimal separator.
  • Geographic names exactly match labels used by geographic files.
  • Data match the latest validated report version.

Watch for manual changes

Do not modify codes, column names or keys used by site filters. If a correction is needed, correct the export or source file, then replace the entire sheet.

3. Publish the sheet as CSV

In Google Sheets, publish the sheet for the country page so the site can read it as CSV. Use a URL ending with output=csv and retain it for WordPress configuration.

  • Publish only the sheet to use, not necessarily the entire workbook.
  • Check the URL in a private window: it must download or display CSV without requiring sign-in.
  • Check that accents, numeric values and headers are present in the published file.

Making public ≠ sharing for editing

The sheet can remain limited to people authorised to edit it. The CSV must, however, be readable by the website without a Google account.

4. Create the country page in WordPress

Once the report and CSV are accessible, create or update the country page using the CTI template. Text fields explain the results; the published CSV remains the data source used by charts.

FieldExpected contentWriting guidance
Title and URLCountry name, slug and hierarchy defined by the site.Use the same country and ISO code as in GitHub and the data.
BackgroundSurvey and Red Cross / system context: CTI purpose, period, coverage, programme or emergency context.One short, factual paragraph, ideally under 100 words.
LeadIntroductory sentence or key message visible at the top of the page.Write a clear summary without over-interpreting the results.
Last updateDate when the page was updated or results were published.Use a consistent date format on all pages.
SupportOrganisations that supported, implemented or funded the survey, where relevant.Use validated institutional names.
LevelCoverage level: National level, or the relevant subnational level.Describe the actual survey scope, not the theoretical administrative scope.
ResultsSurvey overview: data-collection dates, geographic coverage, sample size, target population, context and purpose.This is a narrative field: do not paste the CSV URL or content here.
Population profileOverview of respondent profile and comparison with the population: age, gender, location and any representation gaps.State sampling limitations neutrally.
Drivers of community trustBrief interpretation of drivers: highest and lowest results, and relevant differences between competencies and values.Describe associations or differences; do not infer causality.
Voices of communityOne or more quotes or contributions: title, quote / text and source.Obtain required consent, anonymise where necessary and never invent a testimonial.
Socio-Economic analysisBrief analysis of differences observed by available socio-economic or demographic characteristics.Focus on useful, statistically interpretable differences.
Geographic analysisSummary of variation across geographic areas where coverage and sample sizes allow analysis.Do not draw conclusions for insufficiently represented areas.

Data connection

The published Google Sheets sheet provides chart data. Check that country, module and year in the CSV match the page. The Results field is an explanation for readers, not a data source.

Optional fields

If an analysis or quote is unavailable or inappropriate, leave the relevant field blank. A section must never be filled with unsupported interpretation or generic content.

5. Complete the Story section

In the current WordPress version, open the Story section after completing the page’s basic information. It contains the editorial narrative: Geographic analysis, Findings, Insights, Report buttons, Recommendations and Limitations. This content must align with the report without duplicating it in full.

Story fieldExpected contentRecommended format
FindingsSummary of the main results: overall level, strengths and areas for improvement, key differences by profile or area, and practical implications.Two to three short, factual paragraphs in accessible language.
InsightsKey messages highlighted on the page.Add three cards where needed: each with a short title and one explanatory sentence. Include scores only where they help explain the message.
Report buttonsButtons linking to available deliverables, primarily the full report hosted in GitHub.For each button, enter a clear label and complete URL. Test every link in a new tab before publishing.
RecommendationsActions proposed from the results to strengthen or maintain trust.Up to six recommendations: an action-oriented title and short, concrete, context-specific description.
LimitationsLimitations of coverage, method, data quality or interpretation.One short, transparent paragraph. Specify, for example, under-represented areas, small sample sizes or lack of national representativeness.

A useful distinction

Findings explain the full set of results; insights extract the most important messages; recommendations translate them into possible actions. Avoid repeating the same text in all three fields.

Report links

The first button should link to the full CTI report in /summary/ISO-code/. Add a PDF button, executive summary or other deliverable only when it is validated and publicly accessible.

6. Final checks before publication

  • The final report is accessible from /summary/ISO-code/.
  • The ISO code is consistent across GitHub, the data sheet and WordPress.
  • Exported data have been pasted with their headers, without blank rows or duplicates.
  • The CSV link works without a Google sign-in.
  • Scores, years, labels and translations match the validated report.
  • Maps use the correct geographic entity names.
  • The Background, Lead, Results and Population profile fields are completed and reviewed.
  • Findings, Insights, recommendations and limitations are consistent with the report.
  • Every report button leads to a public, validated deliverable.
  • Quotes, socio-economic analysis and geographic analysis are sourced or left blank.
  • The WordPress page displays charts and the report link without error.
  • The page has been tested in a private window and on mobile before publication.

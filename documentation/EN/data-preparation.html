Data preparation

Prepare and quality-check your survey before calculating the Community Trust Index. This stage ensures reliable, comparable data that are ready for analysis.

What this stage prepares

Preparation starts as soon as the survey export is received. It preserves a raw source, creates a consistent working file and documents the decisions needed before analysis.

01

Survey file

A clean export with one row per respondent, a unique identifier and the variables expected by the questionnaire.

02

Population data

Reference tables aligned with the target population and the variables selected for weighting.

03

Quality checks

Documented checks on eligibility, duplicates, response options and geography.

The preparation workflow

Follow these four steps in order. They apply to every module, with question mappings specific to the Institutional or Early Warning module.

Archive

Keep the original, unmodified export received from Kobo, ODK or the data-collection tool.

Prepare

Create a working copy and check the structure, eligibility and required variables.

Harmonise

Standardise labels, age groups and geographic levels without overwriting source data.

Validate

Check alignment with population tables and record every decision in a log.

1. Prepare the survey file

The analysis file must contain one row per respondent. Keep technical question names: the configuration file will later link them to report labels and indicators.

Every respondent must have a unique and stable identifier, ideally the one created by the data-collection platform. Column headers must also be unique.

Analysis sample

Define the inclusion rules at this stage: consent, completed form, target population, any deduplication and, where the protocol requires it, a question about knowledge of the Red Cross or National Society. These rules must be identical in the configuration, results and report.

Key principle

Never modify the source file. Work on a copy and record every transformation: date, variable concerned, action taken and rationale.

Disaggregation and weighting

Age, gender and location are the minimum requirements. Up to three additional strata may be added for weighting. For disaggregated analysis, use at least the sampling strata: they enable representative analysis where sample sizes allow.

2. Harmonise the data

Use a harmonised variable when different values refer to the same category. Always retain the original value alongside this working variable.

Age

For analysis of people aged 18 and above, use the groups 18-29, 30-39, 40-49, 50-59 and 60+. The package standardises this information as Age_group.

Responses and special values

Do not confuse a blank cell, a “Don’t know” response, a refusal and a question not asked because of skip logic. These cases must remain distinct in the working file.

CTI questions and coding

Questions used to calculate CTI scores are standardised. Their code must follow a stable convention: a prefix for the dimension or pillar, followed by a suffix for the sub-dimension, in the form DIMENSION_Subdimension. A reference table of questions and codes will be added to this documentation.

Translations and recoding are defined in the configuration. Response options observed in the export must match the declared mapping.

3. Prepare geography and population data

Area names in the survey must match the administrative levels, population tables and administrative boundaries used for maps. Create a crosswalk table where needed.

Population tables must describe the same target population as the survey, for example people aged 18 and above. They must match collected data exactly: the same age bands, gender categories and regions or administrative levels.

The data model generally includes an age × gender table, a geographic table and up to three additional stratum tables. Tables provide the counts or proportions used for weighting.

Where to find the data

Prioritise the national statistics office and census data. Depending on the context, sources may also include the World Bank, MICS surveys or Demographic and Health Surveys (DHS). Always record the source, reference year and any recoding or aggregation carried out.

Watch for absent strata

A category present in the population but absent from the sample cannot be automatically corrected through weighting. Flag it and document the methodological decision.

4. Plan profile analysis

Beyond socio-demographic disaggregations, CTI enables score comparisons by respondents’ experience of and relationship with institutions. These analyses enrich interpretation without changing the overall score calculation.

Core questionnaires include questions that create profiles based on interactions with institutions, behaviours, intentions, knowledge or habits. They may be adapted or supplemented for the specific context.

Document in the configuration

For each profile, specify the variable or variables used, the response options included and the rule applied when a respondent can belong to more than one category.

5. Complete quality checks

Before preparing the configuration, check that the working file and reference data are ready for analysis.

  • The raw export is archived and has not been modified.
  • The working file contains one row per respondent and a unique identifier.
  • Eligibility rules are defined and applied.
  • Response options are harmonised without removing source values.
  • Age, gender and location categories match the population data.
  • CTI questions, their coding and respondent profiles are documented.
  • Population tables match the population and area covered by the survey.
  • Corrections and exceptions are recorded in a preparation log.

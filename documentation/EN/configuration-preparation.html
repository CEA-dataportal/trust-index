Configuration file preparation

The configuration file links survey data, population tables, CTI questions and report labels. It must be finalised before running the analysis scripts.

File sheets

The template is based on recent configurations for Madagascar, Burundi and Slovakia. The first three sheets are essential; translations and the simplified table are used according to country and export needs.

1. Complete Parameters

The first column contains fixed keys: do not rename them. The definition column explains their purpose; values is the only column to complete.

File and sheet names must exactly match those in the working folder. Use the same ISO3 code in file names, folders and exports.

Essential parameters

  • data_file, data_tab, code_file and code_tab link the survey file and dictionary.
  • pop_file, demo_tab, geo_tab and strata1_tab to strata3_tab link the population data.
  • subset_field and subset_value define the eligibility filter, where needed.
  • age_col and gender_col must use the exact survey-file column names.
  • shp_folder, adm0_file, adm1_file and adm2_file declare administrative boundaries used for maps.

Keep strict consistency

Age, gender, geography and stratum categories declared here must match survey data and population tables. A label difference is enough to prevent weighting or charts from working correctly.

2. Prepare administrative boundaries

CTI maps use country shapefiles. Download them from GADM, then keep the associated files together in the project folder.

Download

Select the country in GADM and download the shapefile archive.

Store

Extract all files into {country}/SHP/, within the project folder.

Identify

Select the required administrative level and check the name column in the .dbf.

Configure

Enter file names and matching columns without changing them.

Read GADM levels

The file suffix indicates the geographic level. Use the exact downloaded file name in Parameters; the prefix may vary by version and country code.

SuffixContentField to complete
_0Country boundariesadm0_file
_1First administrative division (admin 1)adm1_file
_2Second administrative division (admin 2)adm2_file
_3 and aboveAdditional administrative levels, if availableUse only if the country workflow requires it

Complete names and columns

  • Set shp_folder = SHP and the complete file names, for example gadm41_MDG_1.shp in the adm*_file fields.
  • Open the matching .dbf file in Excel. Identify the column containing geographic entity names and enter it in adm1_shp or adm2_shp.
  • Set geoname_survey and geoname_pop to the columns containing area names in the survey and population data.

Essential check

Compare area names in the .dbf, survey and population table before running the analysis. Spelling, accents, hyphens, spaces and administrative level must match exactly.

Keep .shp, .shx, .dbf and other GADM files together. Do not modify names in the .dbf: instead harmonise working values or use a crosswalk table if needed.

3. Describe variables in Code

Each row documents one export variable. The first four fields identify and display it; the last three determine its analytical use.

ColumnRoleExample
old_nameExact column or label name in the source export.Q1. Are you at least 18 years old?
variableStable name used by scripts and exports.Age_group, COMP_capability
short_labelShort label for tables and charts.Capability
long_labelExplanatory text for the question or indicator.Do you think the Red Cross is capable of helping people?
categoryVariable analysis type.demo, geo, competency, value
analysisMarks a variable to use for disaggregated analysis.yes
breakdownResponse option that defines a profile or specific series.Yes

4. Use CTI categories and coding

Demographic and geographic variables are classified as demo and geo respectively. Mark analysis = yes for factors that should appear in disaggregated analyses.

For the Institutional module, score questions are classified as competency or value. Their coding uses standard prefixes, for example COMP_capability and VALUES_kindness.

For Early Warning, the category identifies the pillar or question type, for example disaster, detection, dissemination, response, risk or ews. The code keeps the dimension or pillar prefix and sub-dimension suffix, using the format DIMENSION_Subdimension.

Respondent profiles

Use experience, behaviours, intention, knowledge, impact or other questionnaire categories to analyse scores by interactions with institutions, behaviours, intentions, knowledge or habits.

5. Harmonise response options in Answer_mapping

The from column contains the value observed in the survey; to contains its harmonised value. Add a row for every spelling, punctuation, language or specific response option observed in the data.

The score_map group lists response options used for scoring. The answer_likertscale, answer_extra, answer_ews, answer_risk, answer_channel, answer_knowledge, answer_behaviours, answer_intention and answer_yn_map groups harmonise responses used in charts.

Do not recode raw data

Mapping replaces manual transformations in the export. Keep the exact value in from and one reference value in to.

6. Add translations

The translation sheet can replace or supplement labels displayed in the report. Each row links a key to its section and EN, FR and ES versions.

Use this sheet for administrative names, country-specific categories, contextual questions and any text not already in the base translations. Select the report language in Parameters → translation.

The code_table sheet, when used by the country workflow, contains a simplified Code version with variable, short_label and long_label.

One key, one purpose

Do not reuse the same key for two different labels. Keep custom keys simple and stable, for example custom.1, custom.2.

Checklist before running

The configuration file is ready when every reference points to the right file and all questions used are documented unambiguously.

  • The country, ISO3 code, file names and sheet names are completed.
  • The eligibility filter matches the rule used for the survey.
  • Age, gender and geography variables exactly match the survey file.
  • Population files and any strata are correctly referenced.
  • Country GADM shapefiles are kept in the SHP folder, with their .shp, .shx and .dbf files.
  • adm*_file file names and adm*_shp columns exactly match the downloaded files.
  • Area names match between the survey, population tables and shapefile .dbf.
  • All CTI questions have an appropriate code, label and category.
  • Profiles and analysis factors have a clear rule in analysis and breakdown.
  • Every observed response option is covered by Answer_mapping.
  • Context-specific translations are completed in the required languages.
  • Unused optional fields remain blank rather than being filled with a dummy value.

Génération du rapport

Le template R Markdown assemble automatiquement les données pondérées, la configuration du pays, les traductions, les graphiques et les tableaux dans un rapport CTI interactif. L’équipe pays complète le récit et les messages clés ; les scripts standards produisent les analyses.

R MarkdownHTML interactifTélécharger le template Rmd ↓

Ce que fait le template

Le fichier Country-Report-template.Rmd est le document maître du rapport. Lorsqu’il est rendu (« Knit »), il exécute les scripts R requis, calcule les objets d’analyse, insère les graphiques et assemble le texte rédigé pour le pays.

Le format HTML est le format de référence : il conserve la table des matières, les onglets, les boutons de téléchargement et les cartes interactives. Le rapport est autonome grâce à l’option self_contained: true.

Pré-requis

Le fichier de configuration, les données pondérées, les tables de population et les shapefiles doivent déjà être finalisés. Lancez le rapport depuis le dossier du projet et vérifiez que le chemin repo pointe vers le dépôt CTI.

Structure du rapport

Le document combine des contenus narratifs, spécifiques au pays, et des sections calculées automatiquement. Les blocs conditionnels affichent seulement les analyses disponibles pour le module et les variables configurées.

Entrées

Le pays, le module, le fichier de configuration et le chemin de travail sont définis au début du Rmd.

Analyse

Les scripts chargent les données, les paramètres et les traductions, puis préparent les scores et diagnostics.

Rapport

Les textes, graphiques, cartes et tableaux sont insérés dans les rubriques du rapport.

Export

Le rapport HTML est créé et export.R prépare les fichiers de téléchargement et les sorties de données.

1. Paramètres à renseigner au début du Rmd

Le bloc input contient les paramètres qui relient le template au projet pays. Adaptez-les avant de rendre le rapport.

ParamètreRôleExemple
country_nameNom du pays utilisé pour localiser le dossier de travail.Madagascar
config_fileNom exact du fichier de configuration du pays.MDG_configuration.xlsx
moduleModule à analyser. Les valeurs prises en charge sont inst et ews.ews
pathChemin du dossier pays.file.path("..", country_name)
repoChemin du dépôt CTI ; il permet au template d’appeler les scripts partagés./…/trust-index

Rendre le rapport

Dans RStudio, ouvrez le Rmd, vérifiez les paramètres puis utilisez Knit. Vous pouvez aussi utiliser :

rmarkdown::render("Country-Report-template.Rmd")

Ne changez pas le modèle au hasard

Conservez les noms des objets et des chunks standards. Ils contrôlent les affichages conditionnels, les onglets, les cartes et les téléchargements. Toute modification structurelle doit être testée pour les deux modules.

2. Scripts appelés et rôle de chacun

Les scripts standards sont appelés dans un ordre précis. Ils ne doivent normalement pas être modifiés dans le Rmd pays.

GroupeScripts appelésFonction
Modulepalette_[module].R, config_[module].RCharge les couleurs, les dimensions, les préfixes et les paramètres propres au module Institutional ou EWS.
Configuration et donnéessetup.R, read_config.R, load_data.RInitialise l’environnement, lit le fichier de configuration et charge les données ainsi que les tables nécessaires.
Traduction et analysetranslation_v2.R, analysis.RApplique la langue du rapport, prépare les variables et calcule les scores, profils et contrôles statistiques.
Visuels et tableauxcharts_sampling.R, charts_drivers.R, charts_score.R, charts_advanced.R, tables.RCrée les graphiques d’échantillonnage, résultats, facteurs, profils, cartes et tableaux.
Sortiesexport.RProduit les données exportables utilisées par le bouton de téléchargement et les sorties de publication.

3. Ce que l’équipe pays peut modifier

Les zones signalées input-required sont conçues pour être complétées. Elles permettent d’adapter le rapport sans modifier les calculs.

  • Le titre, le pays, le module et le fichier de configuration.
  • Le résumé narratif global et les principaux enseignements.
  • Le texte de l’échantillonnage, du contexte pays et des limites de l’enquête.
  • Les commentaires d’interprétation sur les résultats et les recommandations contextuelles.
  • La langue du rapport et les traductions spécifiques, via le fichier de configuration et l’onglet translation.

À laisser standard

Ne modifiez pas les scripts appelés, les règles de score, les préfixes CTI, les objets de graphiques ni les chunks d’export sans validation technique. Les adaptations pays doivent rester dans la configuration, les traductions et les blocs narratifs du Rmd.

4. Ce que le rapport produit

Les contenus apparaissent selon le module sélectionné, les questions réellement présentes et les contrôles configurés.

01

Résumé et échantillonnage

Messages clés, profil des répondants, répartition géographique, pyramide âge-genre, comparaison avec la population et cartes de couverture.

02

Résultats d’enquête

Drivers, questions contextuelles, risques et EWS, selon les variables disponibles dans le module.

03

Scores CTI

Scores globaux, dimensions ou piliers, facteurs de désagrégation, géographie et profils de répondants.

04

Méthodes et sorties

Tableaux descriptifs, pondération, corrélations, tests statistiques et bouton de téléchargement des données exportées.

Publier en PDF ou Word si nécessaire

Conservez d’abord le HTML comme version de référence : les onglets et cartes Leaflet sont interactifs. Pour une diffusion statique, ajoutez temporairement word_document ou pdf_document à la section output du YAML, puis rendez explicitement le format souhaité.

rmarkdown::render("Country-Report-template.Rmd", output_format = "word_document")

rmarkdown::render("Country-Report-template.Rmd", output_format = "pdf_document")

Conseil de publication

Vérifiez la version statique avant diffusion : les onglets deviennent des rubriques simples, les cartes interactives doivent disposer d’une version statique et le PDF nécessite une installation LaTeX, par exemple TinyTeX.

Pour Word, prévoyez une relecture de mise en page et, si nécessaire, un document de référence .docx. Ne remplacez pas le rapport HTML validé.

Checklist avant publication

  • Le pays, le module, le fichier de configuration et le chemin du dépôt sont corrects.
  • Les données pondérées et les tables de population utilisées sont les versions validées.
  • Les textes marqués input-required ont été remplacés par le contenu pays.
  • Les messages clés, la description de l’échantillonnage et les limites sont relus.
  • Les graphiques et tableaux correspondent aux données finales.
  • Les cartes et téléchargements fonctionnent dans le rapport HTML.
  • Les traductions spécifiques ont été vérifiées dans la langue de publication.
  • La version PDF ou Word, si produite, a été relue après rendu.

Étape suivante

Lorsque le rapport et les exports sont validés, préparez les données de publication pour les rendre disponibles sur le site web du CTI.

Publication de la page pays

Après validation du rapport, publiez le rapport et les données dans les emplacements attendus, puis créez la page pays dans WordPress. La page web lit les données depuis le CSV publié : sa qualité dépend donc des fichiers mis en ligne.

Ce que vous publiez

La country page réunit un rapport complet et une visualisation web des résultats. Le rapport HTML reste la source détaillée ; les graphiques de la page pays sont alimentés par les tables exportées puis publiées au format CSV.

Utilisez le même code ISO à trois lettres dans GitHub, le nom du jeu de données et les paramètres de la page. Par exemple, pour Madagascar : MDG.

Avant de commencer

Validez le rapport, les données exportées et les messages clés. Toute modification des scores ou des libellés doit être faite avant la publication du CSV et la vérification finale de la page WordPress.

Le flux de publication

Suivez ces étapes dans cet ordre afin que la page WordPress puisse lire le rapport et les données disponibles en ligne.

Déposer le rapport

Ajoutez le rapport final dans GitHub, dans le dossier du pays.

Préparer les données

Copiez les exports dans le Google Spreadsheet destiné à la publication.

Publier le CSV

Rendez la feuille accessible au format CSV et contrôlez l’URL publiée.

Créer et vérifier

Créez la page WordPress, renseignez ses paramètres et testez le rendu public.

1. Publier le rapport dans GitHub

Le rapport final doit être disponible dans le dépôt CTI avant de créer le lien depuis la country page.

ActionEmplacement / règleContrôle
Créer ou ouvrir le dossier pays/summary/ISO-code/, par exemple /summary/MDG/.Le code ISO est identique à celui utilisé pour les données et la page.
Ajouter le rapport validéDéposez la version HTML finale du rapport dans ce dossier, en suivant la convention de nommage du dépôt.Ouvrez le fichier depuis GitHub et vérifiez son affichage ainsi que les liens internes.
Conserver la version de référenceAjoutez aussi la version PDF ou Word si elle est diffusée officiellement.Le lien « rapport complet » de la page pays pointe vers la bonne version.

Bon réflexe

Utilisez une pull request lorsque le dépôt est partagé. Elle permet une relecture du lien, du nom de dossier et du rapport avant sa mise à disposition publique.

Ne changez pas le code ISO

Les dossiers, les données et la page doivent tous utiliser le même code. Une différence entre MDG, Madagascar et un autre identifiant empêche généralement les liens ou chargements automatiques de fonctionner.

2. Copier les données exportées dans Google Sheets

Le fichier d’export produit par le rapport fournit les données destinées aux graphiques. Copiez ses données dans le Google Spreadsheet prévu pour alimenter le site.

A

Ouvrir la feuille de publication

Utilisez le Google Spreadsheet central du CTI et ouvrez ou créez l’onglet correspondant au pays et au module.

B

Coller les valeurs

Collez les exports comme valeurs, en conservant la ligne d’en-têtes et les colonnes standardisées.

C

Contrôler la structure

Vérifiez notamment Country, Module, Year, Group, Name, Label, Series et Value.

D

Vérifier les libellés

Conservez les codes et les intitulés nécessaires aux graphiques, y compris les colonnes de traduction lorsqu’elles sont utilisées.

Points de contrôle

  • Il n’y a qu’une seule ligne d’en-têtes et aucune ligne vide au début de la feuille.
  • Les valeurs numériques restent des nombres et utilisent le même séparateur décimal.
  • Les noms géographiques correspondent exactement aux libellés utilisés par les fichiers géographiques.
  • Les données correspondent à la dernière version validée du rapport.

Attention aux modifications manuelles

Ne modifiez pas les codes, les noms de colonnes ou les clés qui servent aux filtres du site. Si une correction est nécessaire dans les résultats, corrigez l’export ou le fichier source puis remplacez l’onglet complet.

3. Publier la feuille au format CSV

Dans Google Sheets, publiez l’onglet destiné à la page pays afin que le site puisse le lire sous forme de CSV. Utilisez une URL qui se termine par output=csv et conservez-la pour la configuration WordPress.

  • Publiez uniquement l’onglet à utiliser, pas nécessairement l’ensemble du classeur.
  • Vérifiez l’URL dans une fenêtre privée : elle doit télécharger ou afficher un CSV sans demander de connexion.
  • Contrôlez que les accents, les valeurs numériques et les en-têtes sont bien présents dans le fichier publié.

Rendre public ≠ partager pour édition

La feuille peut rester réservée aux personnes autorisées à l’éditer. Le CSV doit en revanche être accessible en lecture par le site web, sans compte Google.

4. Créer la country page dans WordPress

Une fois le rapport et le CSV accessibles, créez ou mettez à jour la page pays avec le modèle CTI. Les champs de texte expliquent les résultats ; le CSV publié reste la source utilisée par les graphiques.

ChampContenu attenduConseil de rédaction
Titre et URLNom du pays, slug et hiérarchie prévus par le site.Utilisez le même pays et le même code ISO que dans GitHub et les données.
BackgroundContexte de l’enquête et de la Croix-Rouge / du système concerné : objet du CTI, période, couverture et contexte de programme ou d’urgence.Un paragraphe court, factuel, idéalement moins de 100 mots.
LeadPhrase d’introduction ou message principal visible en tête de page.Formulez une synthèse claire, sans surinterpréter les résultats.
Last updateDate de mise à jour de la page ou de publication des résultats.Utilisez un format de date cohérent sur toutes les pages.
SupportOrganisations ayant soutenu, mis en œuvre ou financé l’enquête, lorsque cela est pertinent.Employez les noms institutionnels validés.
LevelNiveau de couverture : National level, ou le niveau infranational concerné.Décrivez le périmètre réel de l’enquête, et non le périmètre administratif théorique.
ResultsRésumé de l’enquête : dates de collecte, couverture géographique, taille de l’échantillon, population concernée, contexte et objectif.Ce champ est narratif : n’y collez pas l’URL ou le contenu du CSV.
Population profilePrésentation du profil des répondants et de la comparaison avec la population : âge, genre, localisation et éventuels écarts de représentation.Signalez les limites d’échantillonnage de façon neutre.
Drivers of community trustLecture courte des drivers : résultats les plus élevés ou les plus faibles, et différences pertinentes entre compétences et valeurs.Décrivez des associations ou écarts ; n’inférez pas de causalité.
Voices of communityUne ou plusieurs citations ou contributions : titre, citation / texte et source.Obtenez l’accord nécessaire, anonymisez si besoin et n’inventez jamais de témoignage.
Socio-Economic analysisAnalyse courte des différences observées selon les caractéristiques socio-économiques ou démographiques disponibles.Concentrez-vous sur les écarts utiles et statistiquement interprétables.
Geographic analysisSynthèse des variations entre zones géographiques, lorsque la couverture et les tailles d’échantillon permettent l’analyse.Ne tirez pas de conclusion pour les zones insuffisamment représentées.

Connexion des données

La feuille Google Sheets publiée fournit les données des graphiques. Vérifiez que le pays, le module et l’année présents dans le CSV correspondent à ceux de la page. Le champ Results est une explication pour le lecteur, pas une source de données.

Champs facultatifs

Si une analyse ou une citation n’est pas disponible ou appropriée, laissez le champ concerné vide. Une section ne doit jamais être remplie avec une interprétation non étayée ou un contenu générique.

5. Compléter la section Story

Dans la version actuelle de WordPress, ouvrez la section Story après avoir renseigné les informations de base de la page. Elle regroupe le récit éditorial : Geographic analysis, Findings, Insights, Report buttons, Recommendations et Limitations. Ces contenus doivent être cohérents avec le rapport, sans en reproduire tout le contenu.

Champ StoryContenu attenduFormat recommandé
FindingsSynthèse des principaux résultats : niveau général, forces et axes d’amélioration, écarts importants entre profils ou territoires et implication pratique.Deux à trois courts paragraphes, factuels et rédigés en langage accessible.
InsightsMessages clés mis en avant sur la page.Ajoutez trois cartes au besoin : un titre court et une phrase d’explication chacune. Citez les scores seulement s’ils aident à comprendre le message.
Report buttonsBoutons vers les livrables disponibles, en priorité le rapport complet placé dans GitHub.Pour chaque bouton, saisissez un libellé explicite et l’URL complète. Testez chaque lien dans un nouvel onglet avant de publier.
RecommendationsActions proposées à partir des résultats pour renforcer ou maintenir la confiance.Jusqu’à six recommandations : titre orienté vers l’action et description courte, concrète et spécifique au contexte.
LimitationsLimites de couverture, de méthode, de qualité des données ou d’interprétation.Un court paragraphe transparent. Précisez, par exemple, les zones sous-représentées, les faibles effectifs ou l’absence de représentativité nationale.

Une distinction utile

Les findings expliquent l’ensemble des résultats ; les insights en extraient les messages les plus importants ; les recommendations les traduisent en actions possibles. Évitez de répéter le même texte dans les trois champs.

Liens de rapport

Le premier bouton doit renvoyer vers le rapport CTI complet dans /summary/ISO-code/. Ajoutez un bouton PDF, une note de synthèse ou un autre livrable uniquement lorsqu’il est validé et publiquement accessible.

6. Contrôle final avant publication

  • Le rapport final est accessible depuis /summary/ISO-code/.
  • Le code ISO est cohérent entre GitHub, la feuille de données et WordPress.
  • Les données exportées ont été collées avec leurs en-têtes, sans ligne vide ni doublon.
  • Le lien CSV fonctionne sans connexion Google.
  • Les scores, les années, les libellés et les traductions correspondent au rapport validé.
  • Les cartes utilisent les bons noms d’entités géographiques.
  • Les champs Background, Lead, Results et Population profile sont renseignés et relus.
  • Les Findings, Insights, recommandations et limites sont cohérents avec le rapport.
  • Chaque bouton de rapport dirige vers un livrable public et validé.
  • Les citations, analyses socio-économiques et analyses géographiques sont sourcées ou laissées vides.
  • La page WordPress affiche les graphiques et le lien de rapport sans erreur.
  • La page a été testée dans une fenêtre privée et sur mobile avant publication.

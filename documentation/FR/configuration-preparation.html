Préparation du fichier de configuration

Le fichier de configuration relie les données d’enquête, les tables de population, les questions CTI et les libellés du rapport. Il doit être finalisé avant de lancer les scripts d’analyse.

Les onglets du fichier

Le modèle est fondé sur les configurations récentes de Madagascar, Burundi et Slovakia. Les trois premiers onglets sont essentiels ; les traductions et la table simplifiée sont utilisées selon les besoins du pays et de l’export.

01

Parameters

Déclare les fichiers, les variables, la géographie, les sources et les paramètres de sortie.

02

Code

Associe chaque colonne ou question de l’enquête à une variable, un libellé et une catégorie analytique.

03

Answer_mapping

Harmonise les modalités collectées avec les valeurs utilisées par les scores et les graphiques.

04

translation

Ajoute ou adapte les libellés affichés en anglais, français et espagnol. code_table est un onglet simplifié optionnel.

Ressources à utiliser

Téléchargez le modèle avant de commencer et utilisez le répertoire GADM pour récupérer les limites administratives du pays.

Ordre de préparation recommandé

Commencez par les liens vers les fichiers, puis décrivez les variables du questionnaire. Les mappings et traductions viennent ensuite.

Renseigner

Indiquez le pays, les fichiers d’enquête et de population, les sources et les paramètres géographiques.

Mapper

Reliez les noms source à des noms de variables stables, des libellés clairs et des catégories CTI.

Harmoniser

Recoder les modalités de réponse dans Answer_mapping sans modifier l’export brut.

Vérifier

Contrôlez que chaque nom de variable, valeur et onglet correspond exactement aux fichiers utilisés.

1. Renseigner Parameters

La première colonne contient des clés fixes : ne les renommez pas. La colonne definition précise leur rôle ; la colonne values est la seule à compléter.

Les noms de fichiers et d’onglets doivent correspondre exactement à ceux présents dans le dossier de travail. Utilisez le même code ISO3 dans les noms de fichiers, les dossiers et les exports.

Paramètres essentiels

  • data_file, data_tab, code_file et code_tab relient le fichier d’enquête et le dictionnaire.
  • pop_file, demo_tab, geo_tab et strata1_tab à strata3_tab relient les données de population.
  • subset_field et subset_value définissent, si nécessaire, le filtre d’éligibilité.
  • age_col et gender_col doivent reprendre les noms exacts des colonnes du fichier d’enquête.
  • shp_folder, adm0_file, adm1_file et adm2_file déclarent les limites administratives utilisées pour les cartes.

Conserver une cohérence stricte

Les catégories d’âge, genre, géographie et strates déclarées ici doivent correspondre aux données d’enquête et aux tables de population. Une différence de libellé suffit à empêcher la pondération ou les graphiques de fonctionner correctement.

2. Préparer les limites administratives

Les cartes CTI utilisent les shapefiles du pays. Téléchargez-les depuis GADM, puis conservez les fichiers associés ensemble dans le dossier du projet.

Télécharger

Sélectionnez le pays dans GADM et récupérez l’archive des shapefiles.

Ranger

Décompressez tous les fichiers dans {pays}/SHP/, au niveau du dossier du projet.

Identifier

Choisissez le niveau administratif nécessaire et vérifiez la colonne des noms dans le .dbf.

Configurer

Reportez les noms de fichiers et les colonnes de correspondance, sans les modifier.

Lire les niveaux GADM

Le suffixe du fichier indique le niveau géographique. Utilisez le nom exact du fichier téléchargé dans Parameters ; le préfixe peut varier selon la version et le code du pays.

SuffixeContenuChamp à renseigner
_0Limites du paysadm0_file
_1Première division administrative (admin 1)adm1_file
_2Deuxième division administrative (admin 2)adm2_file
_3 et suivantsNiveaux administratifs additionnels, si disponiblesUtiliser seulement si le flux du pays le prévoit

Renseigner les noms et les colonnes

  • Indiquez shp_folder = SHP et les noms de fichiers complets, par exemple gadm41_MDG_1.shp, dans les champs adm*_file.
  • Ouvrez le fichier .dbf correspondant dans Excel. Identifiez la colonne contenant le nom des entités géographiques et renseignez-la dans adm1_shp ou adm2_shp.
  • Renseignez geoname_survey et geoname_pop avec les colonnes contenant les noms de zones dans l’enquête et les données de population.

Vérification indispensable

Comparez les noms de zones dans le .dbf, l’enquête et la table de population avant l’exécution. L’orthographe, les accents, les traits d’union, les espaces et le niveau administratif doivent correspondre exactement.

Gardez ensemble les fichiers .shp, .shx, .dbf et les autres fichiers livrés par GADM. Ne modifiez pas les noms dans le .dbf : harmonisez plutôt les valeurs de travail ou utilisez une table de correspondance si nécessaire.

3. Décrire les variables dans Code

Chaque ligne documente une variable de l’export. Les quatre premiers champs servent à la retrouver et à l’afficher ; les trois derniers déterminent son utilisation analytique.

ColonneRôleExemple
old_nameNom exact de la colonne ou du libellé dans l’export source.Q1. Avez-vous au moins 18 ans ?
variableNom stable utilisé par les scripts et les exports.Age_group, COMP_capability
short_labelLibellé court pour les tableaux et graphiques.Capability
long_labelTexte explicite de la question ou de l’indicateur.Do you think the Red Cross is capable of helping people?
categoryType d’analyse de la variable.demo, geo, competency, value
analysisIndique une variable à utiliser pour l’analyse désagrégée.yes
breakdownModalité qui définit un profil ou une série spécifique.Yes

4. Utiliser les catégories et codifications CTI

Les variables démographiques et géographiques sont classées respectivement en demo et geo. Marquez analysis = yes pour les facteurs qui doivent apparaître dans les analyses désagrégées.

Pour le module Institutional, les questions de score sont classées en competency ou value. Leur codification suit les préfixes standard, par exemple COMP_capability et VALUES_kindness.

Pour EWS, la catégorie identifie le pilier ou le type de question, par exemple disaster, detection, dissemination, response, risk ou ews. Le code conserve le préfixe de la dimension ou du pilier et le suffixe de la sous-dimension, selon le format DIMENSION_Sousdimension.

Profils de répondants

Utilisez experience, behaviours, intention, knowledge, impact ou d’autres catégories prévues par le questionnaire pour analyser les scores selon les interactions avec les institutions, comportements, intentions, connaissances ou habitudes.

5. Harmoniser les modalités dans Answer_mapping

La colonne from reprend la valeur observée dans l’enquête ; la colonne to contient sa valeur harmonisée. Ajoutez une ligne pour chaque orthographe, ponctuation, langue ou modalité particulière observée dans les données.

Le groupe score_map liste les modalités utilisées pour le score. Les groupes answer_likertscale, answer_extra, answer_ews, answer_risk, answer_channel, answer_knowledge, answer_behaviours, answer_intention et answer_yn_map harmonisent les réponses utilisées dans les graphiques.

Ne recodez pas les données brutes

Le mapping remplace les transformations manuelles dans l’export. Conservez la valeur exacte dans from et une seule valeur de référence dans to.

6. Ajouter les traductions

L’onglet translation permet de remplacer ou compléter les libellés affichés dans le rapport. Chaque ligne associe une clé à sa section et aux versions EN, FR et ES.

Utilisez cet onglet pour les noms administratifs, les catégories spécifiques au pays, les questions contextuelles et tout texte qui ne figure pas déjà dans les traductions de base. Sélectionnez la langue du rapport dans Parameters → translation.

L’onglet code_table, lorsqu’il est utilisé par le flux du pays, contient une version simplifiée de Code avec variable, short_label et long_label.

Une clé, une seule intention

Ne réutilisez pas une même clé pour deux libellés différents. Conservez les clés personnalisées sous une forme simple et stable, par exemple custom.1, custom.2.

Checklist avant l’exécution

Le fichier de configuration est prêt lorsque toutes les références pointent vers les bons fichiers et que les questions utilisées sont documentées sans ambiguïté.

  • Le pays, le code ISO3, les noms de fichiers et d’onglets sont renseignés.
  • Le filtre d’éligibilité correspond à la règle retenue pour l’enquête.
  • Les variables âge, genre et géographie correspondent exactement au fichier d’enquête.
  • Les fichiers de population et les éventuelles strates sont correctement référencés.
  • Les shapefiles GADM du pays sont regroupés dans le dossier SHP, avec leurs fichiers .shp, .shx et .dbf.
  • Les noms de fichiers adm*_file et les colonnes adm*_shp correspondent exactement aux fichiers téléchargés.
  • Les noms de zones correspondent entre l’enquête, les tables de population et le .dbf du shapefile.
  • Toutes les questions CTI ont un code, un libellé et une catégorie appropriée.
  • Les profils et facteurs d’analyse ont une règle claire dans analysis et breakdown.
  • Chaque modalité observée est couverte par Answer_mapping.
  • Les traductions spécifiques au contexte sont complétées dans les langues nécessaires.
  • Les champs optionnels non utilisés restent vides plutôt que d’être remplis par une valeur fictive.

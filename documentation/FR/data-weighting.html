Calcul des pondérations

Le raking ajuste la contribution de chaque répondant afin que l’échantillon pondéré reproduise les marges de population disponibles. Il est réalisé après le nettoyage des données et avant la préparation finale de la configuration CTI.

Objectif et résultat attendu

La pondération corrige les écarts entre la structure de l’échantillon et celle de la population de référence. Elle ne modifie ni les réponses brutes ni les catégories collectées : elle attribue un poids à chaque répondant pour les analyses et les graphiques.

Le script utilise le raking, ou calage itératif sur marges. Cette méthode ajuste simultanément plusieurs dimensions sans multiplier des poids séparés, ce qui réduit le risque de poids instables.

Avant de commencer

Les données d’enquête doivent être nettoyées, avec une ligne par répondant et des catégories harmonisées. Les données de population doivent couvrir les mêmes tranches d’âge, genres et entités géographiques.

Démarche recommandée

Préparez les marges avant de lancer le script. Un écart de libellé entre l’enquête et la population doit être résolu avant le calcul.

Préparer

Vérifiez le fichier d’enquête, le fichier de population et leurs onglets.

Choisir les marges

Utilisez âge × genre et la géographie, puis ajoutez les strates justifiées.

Contrôler

Comparez toutes les catégories des deux sources avant l’exécution.

Calculer

Lancez le raking, plafonnez les poids et analysez les diagnostics.

1. Préparer les marges de population

Les marges représentent la répartition de la population dans chacune des dimensions retenues. Les noms de niveaux doivent être strictement identiques aux valeurs présentes dans les données d’enquête.

MargeMinimum / optionStructure attendue dans le fichier de population
Âge × genreMinimum requisOnglet age : AGEgroup, Gender, Freq. Les strates sont construites sous la forme 18-29_Female.
GéographieMinimum requisOnglet geo : la colonne des zones et Pop. Choisir le même niveau administratif que dans l’enquête.
Strates supplémentairesJusqu’à 3, si des marges fiables sont disponiblesPar exemple éducation ou emploi ; chaque onglet contient Level et Percentage.

Choisir les strates

Âge, genre et localisation constituent le socle du calage. Ajoutez ensuite jusqu’à trois strates lorsque les données de population sont disponibles, fiables et correspondent aux catégories collectées. Les strates doivent rester compatibles avec la taille de l’échantillon.

Les variables utilisées dans l’enquête et la population sont déclarées dans le script : geo_var1 et geo_var2 pour la géographie, puis flex_survey_vars et flex_tabs pour les strates additionnelles.

Attention aux petites cellules

Une strate détaillée est utile seulement si toutes ses catégories sont présentes dans l’échantillon. Si une catégorie de population est absente de l’enquête, le raking s’arrête : regroupez des modalités ou retirez cette marge avant de recommencer.

2. Vérifier les correspondances

Avant l’exécution, comparez les valeurs uniques de chaque variable de calage avec les marges correspondantes. Il ne doit y avoir ni catégorie manquante, ni catégorie supplémentaire dans l’échantillon.

  • Les tranches d’âge sont identiques, par exemple 18-29, 30-39, 40-49, 50-59 et 60+.
  • Les catégories de genre sont identiques dans les deux fichiers.
  • Les noms géographiques utilisent la même orthographe, casse, accents, traits d’union et espaces.
  • Les strates optionnelles emploient les mêmes libellés dans l’enquête et dans les marges de population.

Causes fréquentes d’erreur

Une catégorie peut disparaître après l’exclusion des valeurs manquantes sur une autre strate. Vérifiez aussi les espaces invisibles, les tirets différents et les changements de majuscules/minuscules.

3. Lancer le raking et stabiliser les poids

Le script crée un plan d’enquête avec un poids initial de 1, puis calibre les poids pour que les marges pondérées correspondent aux proportions de population.

01

Calage itératif

Le raking utilise toutes les marges valides simultanément, avec un maximum de 50 itérations et une tolérance de convergence de 1e-6.

02

Traitement des cas non calés

Les répondants complets et présents dans toutes les marges sont utilisés pour le calage. Dans la sortie du script, les cas non inclus reçoivent un poids de 1.

03

Plafonnement

Les poids issus du raking sont plafonnés à 4 afin de limiter l’influence excessive d’un petit nombre de répondants.

04

Normalisation

Les poids plafonnés sont ensuite divisés par leur moyenne : la moyenne finale des poids est égale à 1.

Conceptuellement, le poids augmente pour les groupes sous-représentés et diminue pour les groupes surreprésentés. Le raking détermine l’ajustement conjoint ; il ne faut donc pas multiplier manuellement des ratios par strate.

4. Lire les diagnostics

Ne validez pas les poids sans examiner le résumé global et le tableau par strate produits par le script.

IndicateurCe qu’il permet de vérifierPoint d’attention
MeanLa normalisation des poids.Doit être proche de 1.
Min / MaxL’étendue des poids attribués.Le maximum final ne dépasse pas 4.
SD / CVLa dispersion des poids.Une forte dispersion signale un calage exigeant ou des cellules rares.
Effective sample sizeLa taille d’échantillon après prise en compte des poids : (Σw)² / Σ(w²).Comparez-la à l’effectif initial. Une efficacité de 60–80 % est généralement acceptable ; sous 50 %, revoyez les marges.
strata_weight_summaryLe rapprochement par strate entre effectif, proportion échantillon, proportion population et poids moyen.Vérifiez que les ajustements sont plausibles pour chaque groupe.

Fichier produit

Le script exporte un fichier Excel pondéré dans le dossier du pays. Il sert ensuite de base aux analyses CTI et contient :

  • data : les données d’enquête avec la colonne weight ;
  • weight_summary : le résumé global des poids ;
  • strata_weight_summary : le diagnostic détaillé par marge et par strate.

Traçabilité

Conservez la version du fichier de population, les paramètres de raking et le fichier pondéré exporté avec le projet. Ils permettent d’expliquer les écarts entre les résultats bruts et pondérés.

Checklist avant la configuration

  • Le fichier d’enquête contient une ligne par répondant et les colonnes de calage attendues.
  • Les marges âge × genre et géographie correspondent aux données collectées.
  • Les strates supplémentaires sont limitées à trois et reposent sur des données de population fiables.
  • Toutes les catégories de population sont présentes dans l’échantillon retenu pour le raking.
  • Les libellés correspondent exactement entre l’enquête et les tables de population.
  • Le poids final est plafonné à 4 puis normalisé à une moyenne de 1.
  • Le résumé des poids et la taille effective d’échantillon ont été vérifiés.
  • Le fichier pondéré et ses diagnostics sont sauvegardés dans le dossier du pays.
